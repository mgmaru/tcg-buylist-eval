# 0017. 採点器のコードは1つのGoのモジュールにまとめ、1つのコマンドから呼ぶ

- ステータス：採用
- 日付：2026-10-28
- 決定者：kajiwara
- 関係するADR：[0012](0012-implementation-language-go.md)（実装言語：Go）、[0016](0016-task-folder-per-task.md)（タスクごとのフォルダ）

## 背景

- 採点器は、タスクごとに中身が違う（[0016](0016-task-folder-per-task.md)）。そのため、採点器のコードをどこに置くかを決める必要がある。
- 採点器はGoで書き、言語に依存しない独立したコマンドとして作る（[0012](0012-implementation-language-go.md)）。

## 検討した選択肢

| 選択肢 | 置き方 | 良い点 | 弱い点 |
|---|---|---|---|
| A. タスクのフォルダの中に置く | `tasks/<タスク名>/grader/` に、タスクごとの採点器のコードを置く | タスクに関わるものが、本当に1か所にそろう | Goのコードがリポジトリのあちこちに散らばる。ビルドやテスト、共通の処理の使い回しがしにくい |
| B. タスクごとに別のコマンドにする | `graders/<タスク名>/` に、タスクごとに別のコマンドを作る | タスクごとに独立している | コマンドが増えるたびに、ビルドや配布の手順が増える。共通の処理（ファイルの読み書き、`metrics.json` の形）を重複して書きやすい |
| **C. 1つのモジュール・1つのコマンドにまとめる** | 1つのGoのモジュールに、コマンドの入口を1つ（`cmd/grader`）置き、タスクごとの採点のロジックをパッケージ（`internal/grader/<タスク名>`）に分ける | Goの一般的な構成。ビルドもテストも1回で済み、共通の処理を使い回せる。コマンドは1つだけ | タスクのデータと、採点のロジックの置き場所が分かれる |

## 決定

**C にする。** 採点器のコードは1つのGoのモジュールにまとめ、1つのコマンドから呼ぶ。

```
cmd/
└── grader/                 ← コマンドの入口（1つ）
internal/
└── grader/
    ├── buylistcardid/      ← 買取表のカード同定の採点のロジック
    └── ...                 ← タスクが増えたら、ここにパッケージを足す
```

- `task.yaml` には、ファイルの場所ではなく、**採点器の名前**（例：`grader: buylist-card-id`）だけを書く（[0016](0016-task-folder-per-task.md)）。
- コマンドは、名前から採点のロジックを選ぶ（例：`grader grade --task buylist-card-id ...`）。
- コマンドの引数や、受け取るもの・返すものの決まりは、別のADRで決める。

## 理由

- **Goの作法に合わせるため。** Goでは、コマンドの入口を `cmd/` に置き、内部のロジックをパッケージに分けるのが一般的な構成である。この構成にすると、ビルド・テスト・依存の管理が1か所で済む。
- **共通の処理を使い回すため。** ファイルの読み書き、スキーマでの確認、`metrics.json` の形などは、どのタスクの採点器でも同じ。1つのモジュールにまとめれば、重複して書かずに済む。
- **呼び出す側（実行スクリプト）を単純にするため。** コマンドが1つなら、実行スクリプトは「名前を渡して呼ぶ」だけでよい。タスクが増えても、呼び方は変わらない。
- A を選ばなかったのは、Goのコードがタスクのフォルダごとに散らばり、ビルドとテストの手間が増えるため。タスクのデータはタスクのフォルダに、コードはGoのモジュールに、と分けるほうが、それぞれの扱いが素直になる。
- B を選ばなかったのは、タスクが増えるたびにコマンドが増え、共通の処理が重複しやすいため。

## 影響

- 設計書 4章の `graders/` を、`cmd/grader` と `internal/grader/<タスク名>` の構成に直す。
- タスクを足すときは、`tasks/<タスク名>/` に加えて、`internal/grader/<タスク名>` のパッケージを足す。設計書 0.3 の「採点器を足すだけ」の「採点器」は、このパッケージのことになる。
- Inspect AI に移る場合も、このコマンドをInspectの採点の部分から呼べばよい（[0012](0012-implementation-language-go.md)）。
