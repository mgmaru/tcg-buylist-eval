# 0037. 採点の結果を「成績」と「診断」の2つで出す

- ステータス：採用
- 日付：2026-10-30
- 決定者：kajiwara
- 関係するADR：[0023](0023-grader-interface.md)（採点器の入出力）、[0024](0024-show-harness-changes-and-effects.md)（改善の差分と結果）、[0033](0033-grading-by-grader-not-langfuse.md)（採点は採点器が行う）、[0038](0038-score-by-assertion.md)〜[0045](0045-card-name-strict-match.md)

## 背景

- 出力のスキーマには、値の一覧（`enum`）がある。一覧にない値を出力すると、どう扱うかを考える中で、「エラーを採点から外すか、間違いとして数えるか」で迷った。
  - 採点から外すと、どこで失敗したかの情報が消える。
  - すべて間違いとして数えると、原因の違う失敗（形式を守れなかった、画像を読み違えた、カードの照合を誤った）が1つの点数に混ざる。
- このプロジェクトの第一の目的は、ハーネスの設計が出力に与える影響を確かめることである。言い換えると、**評価用ハーネスの目的は、被験ハーネスのどこに問題があり、どこを直せばよいかを見えるようにすること** である。
- 失敗の原因によって、直すべき部品が違う。形式の誤りなら出力の形を守らせる部分、価格の読み違いなら画像の読み取り、カードの照合の誤りならカードDB検索（H2）や自己検証（H3）。

## 検討した選択肢

| 選択肢 | 良い点 | 弱い点 |
|---|---|---|
| A. 1つの点数で表す。エラーは採点から外す | 単純 | 失敗の原因が消え、どこを直せばよいかがわからない |
| B. 1つの点数で表す。エラーもすべて間違いとして数える | 単純。厳しい | 原因の違う失敗が混ざり、直す部品がわからない |
| **C. 「成績」と「診断」の2つを出す** | 成績で合否と比較ができ、診断でどこを直すかがわかる。エラーを外すか数えるかの板挟みがなくなる | 採点器が出すものが増える |

## 決定

**C にする。** 採点器は、次の2つを出す。

| | 答える問い | 決め方 |
|---|---|---|
| **成績** | エージェントが断定した答えを、そのまま確定データとして使ってよいか | 結果で決める（[0038](0038-score-by-assertion.md)、[0039](0039-deliverables-and-intermediates.md)） |
| **診断** | 被験ハーネスのどの部品を直せばよいか | 原因で分ける（[0040](0040-intermediate-results-for-diagnosis.md)〜[0042](0042-out-of-vocabulary-values.md)、[0045](0045-card-name-strict-match.md)） |

- 成績は、合格の判定と、構成どうしの比較に使う。
- 診断は、失敗を原因ごとに分け、直すべき部品を示す。1枚のカードに複数の失敗が重なることがあるので、失敗は項目ごとに記録する。
- README に、評価用ハーネスの目的として、この2つを出すことを書く。

## 理由

- **評価用ハーネスの目的が、点数を付けることではなく、直す場所を見えるようにすることだから。** 成績だけでは、どこを直せばよいかがわからない。A・B を選ばなかったのはこのため。
- **成績と診断を分ければ、「外すか数えるか」で迷わずに済むため。** 成績では結果だけを見て数え、診断では原因を残す。どちらの情報も失わない。
- **改善の差分と結果を見えるようにする（[0024](0024-show-harness-changes-and-effects.md)）には、診断が要るため。** 部品を1つ足したとき、成績の変化だけでなく、どの種類の失敗が減ったかを見れば、その部品が狙い通りに効いたかを確かめられる。

## 影響

- 採点器の `grade` が出す `metrics.json` に、成績と診断の両方を入れる。`summarize` が出す `summary.json` には、構成ごとに、成績と、診断の種類ごとの件数を入れる（[0023](0023-grader-interface.md)）。
- レポートには、成績の比較表に加えて、診断の種類ごとの件数と、該当するカードの一覧を出す。
- 設計書の 8章（採点器）と 9章（レポートと失敗分析）を、この形に合わせて直す（TODO 3章）。
