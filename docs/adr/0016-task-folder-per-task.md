# 0016. タスクに関わるものは、タスクごとのフォルダにまとめる

- ステータス：採用
- 日付：2026-10-28
- 決定者：kajiwara
- 関係するADR：[0017](0017-grader-single-go-module.md)（採点器のコードの置き場所）、[0019](0019-gold-schema-machine-readable.md)（正解データの列の定義）、[0020](0020-terms-task-and-sample.md)（タスクとサンプルの言葉、提案）

## 背景

- 設計書 0.3 の第二の目的の基準の1つは、「新しいタスクを、タスクセット・出力のスキーマ・採点器を足すだけで追加できる」こと。
- 今の設計書（4章）では、1つのタスクに関わるもの（タスクの仕様、問題、出力のスキーマ、正解データの定義）が、種類ごとのフォルダ（`docs/`、`tasks/`、`schemas/`）に散らばっている。
- タスクが1つのうちは困らないが、タスクを足すときに、あちこちのフォルダにファイルを足すことになり、何を足せばタスクが成り立つのかが分かりにくい。

## 検討した選択肢

| 選択肢 | 置き方 | 良い点 | 弱い点 |
|---|---|---|---|
| A. 種類ごと（今の設計書） | `tasks/`、`schemas/`、`docs/` に、それぞれのタスクの分を置く | 今の設計書のまま | 1つのタスクが散らばる。タスクを足すときに、どこに何を足すか分かりにくい |
| **B. タスクごと** | 1つのタスクに関わるものを、`tasks/<タスク名>/` の1か所にまとめ、目録として `task.yaml` を置く | タスクを足すときは、フォルダを1つ足すだけ。差し込み口の単位とフォルダの単位が一致する | 設計書 4章のディレクトリ構成を直す必要がある |

## 決定

**B にする。** タスクに関わるデータと仕様は、`tasks/<タスク名>/` にまとめる。フォルダの中には、タスクの目録として `task.yaml` を置き、評価用ハーネスはこのファイルからタスクの中身の場所を知る。

```
tasks/
└── buylist-card-id/              ← タスク（買取表のカード同定。名前は案）
    ├── task.yaml                 ← タスクの目録
    ├── spec.md                   ← タスクの仕様（被験エージェントに渡す説明）
    ├── schemas/
    │   ├── output.schema.json    ← 出力のスキーマ
    │   └── gold.schema.yaml      ← 正解データの列の定義（ADR-0019）
    └── samples/                  ← 1つ1つの問題（言葉は ADR-0020 で決める）
        └── <サンプルのID>/
            ├── meta.yaml
            ├── gold.csv
            └── input.jpg         ← リポジトリには入れない
```

`task.yaml` の中身の例：

```yaml
id: buylist-card-id
version: 1
spec: spec.md
input:
  files: [input.jpg]
output:
  schema: schemas/output.schema.json
gold:
  file: gold.csv
  schema: schemas/gold.schema.yaml
samples: samples/
grader: buylist-card-id            # 採点器の名前（ADR-0017）
pass:                              # 合格ライン（設計書 8.4）
  wrong_rate: {max: 0.02}
  identified_rate: {min: 0.80}
  format_errors: {max: 0}
```

採点器のコードは、このフォルダには置かない（[0017](0017-grader-single-go-module.md)）。

## 理由

- **差し込み口の単位とフォルダの単位を一致させるため。** タスクを足すことが「フォルダを1つ足すこと」になり、第二の目的の基準をそのまま満たせる。何を足せばタスクが成り立つかは、`task.yaml` を見れば分かる。
- **タスクを取り外すのも簡単になるため。** タスクごとにまとまっていれば、フォルダを消すか移すだけで済み、ほかのタスクに影響しない。
- A を選ばなかったのは、タスクが増えるほど、1つのタスクの中身を集めるのが大変になり、足し忘れや消し忘れが起きやすいため。
- `task.yaml` を置くのは、評価用ハーネスが、タスクの中身の場所を決め打ちせずに済むようにするため。タスクによってファイルの名前や数が違っても、目録を読めば分かる。

## 影響

- 設計書 4章（ディレクトリ構成）、5.1・5.2（メタ情報と正解データ）の置き場所を直す。
- TODO 7章・8章の置き場所とファイル名を、この形に合わせて直す。
- `task.yaml` の項目は、ほかのADR（採点器の入出力など）が決まったら見直す。
- タスクの名前（`buylist-card-id`）は案。決めたら記録する。
