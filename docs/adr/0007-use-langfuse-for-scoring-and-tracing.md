# 0007. 記録・採点・比較・観測にLangfuseを使う

- ステータス：採用
- 日付：2026-10-26
- 決定者：kajiwara

## 背景

ハーネスの評価には、次の部品が必要になる。

| 部品 | 内容 | Langfuse |
|---|---|---|
| タスクセット | 評価用の問題と正解データ | ◯ データセット機能 |
| 環境の準備・リセット | 毎回まっさらな環境から始める。手元の環境を守るために隔離する | × |
| エージェントの自動実行 | 指定したモデルと構成で、タスクを自動で解かせる。時間制限と結果の回収も行う | △ 呼び出す処理は自分で書く必要がある |
| 採点 | コードによる採点、LLMによる採点、人間の評価 | ◯ |
| 集計・比較 | 構成ごとのスコアを並べて比べる | ◯ 実験の比較画面 |
| 観測 | 失敗したタスクで何が起きたかを見る | ◎ トレース |

Langfuseは、送られてきたデータを受け取って保存・表示するサーバーである。コンテナを立ち上げたり、エージェントを起動したりする機能はない。そのため、**環境の準備・リセット** と **エージェントの自動実行** は、別の仕組みが受け持つ必要がある（[0008](0008-execution-framework.md)）。

## 検討した選択肢

| 選択肢 | 良い点 | 弱い点 |
|---|---|---|
| Langfuse | トレース・スコア・実験の比較が1か所でできる。設計書でも使う前提になっている（3.1, 9.1） | 環境の準備と実行は持っていない |
| 評価フレームワークの機能だけで済ませる | ツールが1つで済む | トレースや比較の画面は、Langfuseほど充実していないことが多い |
| ローカルのCSV・Markdownだけで済ませる | 手間がない | 失敗したタスクの途中経過を追えない |

## 決定

- **記録・採点・比較・観測** にLangfuseを使う。
- **環境の準備・リセット** と **エージェントの自動実行** は、Langfuse以外の仕組みが受け持つ（[0008](0008-execution-framework.md)）。

次の点は未定で、TODOで決める。

- **いつから使うか**：M0から使うか、設計書どおりM1からにするか（設計書 11章）
- **どこで動かすか**：Langfuseのクラウド版か、AWS上に自分で立てるか
- **トレースの送り方**：Claude CodeのLangfuseプラグインは、Claude Code以外のランタイムでは使えない。ローカルのモデルも含めて、両方のモデルを同じ方法で送れるか（LangfuseのSDK、OpenTelemetryなど）
- **画像を送ってよいか**：トレースには買取表の画像が含まれる

## 影響

- AWS上に自分で立てる場合、IaCの対象と月の費用が増える（[0004](0004-infrastructure-as-code.md)、[0005](0005-gpu-environment.md)）。
- 買取表の画像は店舗の著作物なので（設計書 13章）、Langfuseのクラウド版に送ってよいかを確認する。送れない場合は、画像を除いてトレースを送るか、自分で立てる。
- 採点のロジック自体は自作の採点器で行い、結果をLangfuseにスコアとして送る（設計書 8章）。
