# 0034. サンプルIDは「店舗-地域-YYYYMMDD」にする

- ステータス：採用
- 日付：2026-10-30
- 決定者：kajiwara
- 関係するADR：[0016](0016-task-folder-per-task.md)（タスクごとのフォルダ）、[0020](0020-terms-task-and-sample.md)（タスクとサンプル）、[0035](0035-sample-meta.md)（サンプルのメタ情報）

## 背景

- サンプル（買取表1枚と、その正解データ）は、`tasks/<タスク名>/samples/<サンプルID>/` に置く（[0016](0016-task-folder-per-task.md)）。サンプルごとに変わるファイル（画像、`meta.yaml`、`gold.csv`）は、すべてこのフォルダにまとめる。
- サンプルIDは、フォルダの名前のほか、採点の結果（`metrics.json`）、実行の記録、Langfuseのデータセットなどからも指される。あとで変えると、これらとのつながりが切れる。
- 1枚目のサンプルを作るにあたり、IDの付け方を決める必要があった。1枚目は `magi-nagoya-20261030`（magi 名古屋駅前店、2026年10月30日の買取表）とした。

## 検討した選択肢

| 選択肢 | 例 | 良い点 | 弱い点 |
|---|---|---|---|
| A. 連番 | `sample-001` | 短い。重ならない | IDを見ても、どの買取表かわからない |
| B. 店舗-地域-日付（日付は `YYYY-MM-DD`） | `magi-nagoya-2026-10-30` | どの買取表かわかる。日付が読みやすい | 長い。区切りのハイフンが、店舗・地域の区切りと見分けにくい |
| **C. 店舗-地域-日付（日付は `YYYYMMDD`）** | `magi-nagoya-20261030` | どの買取表かわかる。日付が1つのかたまりになり、区切りと見分けやすい | 日付は少し読みにくい |

## 決定

**C にする。** サンプルIDは `<店舗>-<地域>-<YYYYMMDD>` にする。

| 部分 | 決まり | 例 |
|---|---|---|
| 店舗 | 店舗のチェーンや店の名前を、ローマ字か英字で短く | `magi`、`torekingu` |
| 地域 | 店舗のある地域を、ローマ字で短く。同じチェーンの店舗を区別できればよい | `nagoya`、`akiba` |
| 日付 | **買取表に書かれた更新日**。買取表に書かれていなければ、**投稿日** | `20261030` |

- 使う文字は、小文字の英数字とハイフンだけにする。
- 同じ店舗・同じ日の買取表が2枚以上あれば、2枚目から末尾に `-2`、`-3` を付ける。
- 世代や dev／test などの分類は、IDに入れない。分類は `meta.yaml` に書く（[0035](0035-sample-meta.md)）。
- **一度付けたIDは変えない。**

## 理由

- **IDを見て、どの買取表かわかるようにするため。** 採点の結果や失敗の分析で、サンプルIDを見ることが多い。連番では、毎回 `meta.yaml` を開く必要がある。A を選ばなかったのはこのため。
- **日付を入れるのは、** 同じ店舗でも、日によって買取表の中身が変わるため。保存した日ではなく、買取表の日付にするのは、同じ買取表を別の日に保存しても、同じIDになるようにするため。投稿日で代えるのは、更新日が書かれていない買取表もあるため（1枚目もそうだった）。
- **日付を `YYYYMMDD` にしたのは、** 日付が1つのかたまりになり、店舗・地域の区切りのハイフンと見分けやすいため。B を選ばなかったのはこのため。
- **小文字の英数字とハイフンだけにするのは、** フォルダ名、URL、AWSのタグやS3のキーなどに、そのまま使えるようにするため（AWSのアカウント名の決まりとも、そろえている）。
- **分類をIDに入れないのは、** 世代や dev／test は、あとで変わりうるため。IDに入れると、IDを変えることになる。
- **IDを変えないのは、** 採点の結果や実行の記録が、IDでサンプルを指しているため。

## 影響

- 1枚目のサンプルは `magi-nagoya-20261030` とする。
- サンプルを作る手順（`gold-guideline.yaml` の S-02）で、この決まりに沿ってIDを付ける。
- 見直すきっかけ：店舗や地域の略し方で、迷うことが増えたとき。そのときは、略し方の一覧を作る。
