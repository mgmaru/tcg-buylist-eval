# 0044. モデルの呼び出しでのスキーマの強制は、被験ハーネスの部品とし、H0では使わない

- ステータス：採用
- 日付：2026-10-30
- 決定者：kajiwara
- 関係するADR：[0022](0022-harness-level-and-components.md)（被験ハーネスの段階と部品）、[0030](0030-task-spec-in-yaml.md)（伝え方は被験ハーネスが受け持つ）、[0041](0041-format-error-kinds-and-units.md)（形式の誤り）、[0042](0042-out-of-vocabulary-values.md)（語彙の外の値）

## 背景

- Anthropic API や Ollama には、モデルの呼び出しにスキーマを渡し、その形でしか答えられないようにする仕組みがある（スキーマの強制）。使えば、形式の誤りや語彙の外の値が起きにくくなる。
- ただし、仕組みの中身は公開されていない部分が多く、ブラックボックスである。多くの実装は、答えを作る途中で、選べる言葉をスキーマに合うものだけに絞る。そのため、一覧に正しい答えがないとき、モデルは一覧の中のどれかを選ばされる。本当は何と言いたかったのかは、記録に残らない。
- 形式を強く縛ると、答えの質が少し下がるという報告もある。
- 評価用ハーネスの目的は、被験ハーネスのどこを直せばよいかを見えるようにすること（[0037](0037-results-and-diagnosis.md)）。語彙の外で出てきた値は、一覧を直す材料になる（[0042](0042-out-of-vocabulary-values.md)）。

## 検討した選択肢

| 選択肢 | 良い点 | 弱い点 |
|---|---|---|
| A. 評価する側の仕組みとして、どの構成でもスキーマを強制する | 形式の誤りがほぼなくなる | 中身のわからない丸め込みが、すべての成績に入る。モデルが本当は何と言いたかったかが消え、診断の材料がなくなる |
| **B. 被験ハーネスの部品とし、H0では使わない。あとで部品として足して効果を測る** | H0で、モデルの素の答え（語彙の外の値も含む）が見える。強制の効果を、数字で比べられる | H0では、形式の誤りが起きうる |

## 決定

**B にする。**

- スキーマの強制は、**被験ハーネスの部品** とする。評価する側の仕組みにはしない。
- **H0（素の状態）では使わない。** H0では、スキーマはプロンプトに書いて伝えるだけにする。
- あとで、スキーマの強制を部品として足した構成を作り、H0との差（形式の誤り、誤答、保留の変化）を比べる（[0022](0022-harness-level-and-components.md) の、1回に1か所だけ変える決まりに従う）。

## 理由

- **ブラックボックスの丸め込みを、評価する側に入れないため。** 強制は、正しい答えを一覧の中の間違った値に寄せることがありうる。評価する側に入れると、その影響がすべての成績に混ざり、見分けられない。A を選ばなかったのはこのため。
- **中身はわからなくても、効果は数字で確かめられるため。** 部品として足した構成と比べれば、強制が形式の誤りをどれだけ減らし、誤答や保留をどう変えたかがわかる。
- **H0で、モデルの素の答えを見るため。** 強制しなければ、語彙の外の値がそのまま出てくる。これは、一覧を直す材料になる。
- **モデルにどう答えさせるかは、被験ハーネスが受け持つと決めているため**（[0030](0030-task-spec-in-yaml.md)）。スキーマの強制も、答えさせ方の工夫の1つである。

## 影響

- H0の被験ハーネス（TODO 9章）では、スキーマの強制を使わない。
- スキーマの強制を部品として足すときに、部品の名前とやり方（`part`・`variant`）を決める（[0022](0022-harness-level-and-components.md)）。
- H0 の成績には、形式の誤りが含まれうる。合格の判定でそれが問題になったら、強制を足した構成と比べて判断する。
