# 0005. ローカルモデルを動かすGPU環境：AWSのg6.xlarge（米国東部）

- ステータス：採用
- 日付：2026-10-26
- 決定者：kajiwara
- 調査：[AWSの費用](../research/aws-gpu-cost.md)

## 背景

- ローカルのマルチモーダルモデル（[0002](0002-compare-cloud-and-local-models.md)）を動かすGPU環境が必要。作業用のMacでは動かさない。
- 候補は、手元にある別のWindows PC（RTX 3080、VRAM 10GB）か、クラウドのGPUサーバー。クラウドはAWSを使いたいが、コストを調べてから決める。
- 予算：GPUサーバーは月5,000円程度、ほかのサーバー代も合わせて月1万円程度。
- M0の実行回数は少ない（例：2モデル × 3タスク × 3回 ＝ 18回）。GPUを使う時間は数時間で済む見込み。

## 検討した選択肢

| 選択肢 | 良い点 | 弱い点 |
|---|---|---|
| Windows PC（RTX 3080・VRAM 10GB） | 費用は電気代だけ（1時間あたり約11〜14円） | 動かせるのは4ビット量子化の7〜9Bクラスまで。エージェント側からの接続（ネットワークの公開と安全性）を考える必要がある。IaCの経験はWindows（WSL2）の構成管理が中心になる |
| AWSのGPUサーバー（使うときだけ作る） | IaCの経験が最も積める。VRAM 16〜24GBのGPUを選べる。エージェントの実行環境と同じ場所にまとめられる | 時間課金がかかる。新しいアカウントではGPUサーバーの利用枠が0で、申請が必要 |
| AWS以外のGPUクラウド | AWSより安いことがある | 目的の「AWSでのIaCの経験」から外れる |

AWSの主なGPUインスタンス（オンデマンド、調査日 2026-10-26）：

| インスタンス | GPU | 米国東部 | 東京 |
|---|---|---|---|
| g4dn.xlarge | T4・16GB | 0.526ドル／時間 | 約35〜45%高い |
| g6.xlarge | L4・24GB | 0.8048ドル／時間 | 1.1672ドル／時間 |
| g5.xlarge | A10G・24GB | 1.006ドル／時間 | 1.459ドル／時間 |

M0（GPUを月5〜10時間使う）の費用は、ディスクや実行環境を含めて合計約900〜1,650円の見込み。月30時間でも約4,700円で、GPUの予算に収まる。

## 決定

- **GPUサーバーは、AWSの g6.xlarge（L4・VRAM 24GB）をオンデマンドで使う。** リージョンは **米国東部（us-east-1）**。米国西部（us-west-2）は同じ価格なので予備とする。
- **エージェントの実行環境** は、同じリージョン・同じアベイラビリティゾーンの小さいサーバー（t3.small、足りなければt3.medium）に置く。
- どちらも **使うときだけTerraformで作り、終わったら消す**（[0004](0004-infrastructure-as-code.md)）。ディスクも毎回作り直す。
- GPUの利用枠（G・VTインスタンスのオンデマンド）を、米国東部で8 vCPU申請する。
- **Windows PC は予備** とする。利用枠の申請が通らないときや、モデルを手元で試すときに使う（モデルは [0009](0009-models-for-m0.md) の予備のモデル）。

## 影響

- 消し忘れが一番の費用リスクになる。予算のアラートと削除の手順を最初に用意する（[0004](0004-infrastructure-as-code.md)）。
- サーバーを消しても費用が残るもの（状態ファイルのS3、Langfuseのデータ用のディスク）を把握しておく。
- 画像は米国のAWSに置くことになる。利用規約・権利の確認はこの前提で行う（TODO 2章）。
- 利用枠の申請が通るまでの時間は分からない。早めに申請する。
- GPUを月60時間ほど使うと、GPUの予算を超える。M2の前に見直す。
