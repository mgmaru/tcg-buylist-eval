# 0028. パックごとの番号が印刷されていないカードは、M0の対象外にする

- ステータス：提案
- 日付：2026-10-29
- 決定者：kajiwara（未決定。PRでレビューする）
- 関係するADR：[0026](0026-provisional-key-pack-number-variant.md)（仮のキーは「パック＋番号＋仕様」）
- 調査：[docs/research/card-data-sources.md](../research/card-data-sources.md)（3章「番号の付き方」）

## 背景

- 仮のキーは、パック・番号・仕様で作る（[0026](0026-provisional-key-pack-number-variant.md)）。番号は、**パックの中でカードを1つに決める番号**（`055/053` や `001/BW-P` の形）であることを前提にしている。
- しかし、世代によって番号の付き方が違い、この前提が成り立たないカードがある（調査の3章）。

| カード | 番号 | パック＋番号で表せるか |
|---|---|---|
| 旧裏・neo（1996〜2001年） | なし | 表せない |
| VS・web・e・ADV・PCG・DPt・LEGEND・BW以降 | パックごとの番号（`001/141` など） | 表せる |
| DP（DP1〜DP5、DPのデッキ。2006〜2008年） | パックごとの番号はない。ポケモンには「DPBP#」で始まるパックをまたいだ通し番号（1〜530）がある。LV.X・トレーナーズ・エネルギーには、この番号もない | 表せない（下を参照） |
| プロモのうち、番号のないもの（勝利のしるし、基本エネルギーなど。どの世代にもある） | なし（記号だけのものもある） | 表せない |

- **DPBP#は、カードではなくポケモンの種類に付く番号。** 同じポケモンなら、別のパックでも同じ番号になる（パルキアはDP1でもDP3でも #523）。同じパックの中でも、同じ番号のカードが2枚ある（DP2のピカチュウ #026）。そのため、パック＋DPBP#でも、カードは一意に決まらない。
- M0の最初の題材は、BW期の買取表。カードには、パックごとの番号が印刷されている。

## 検討した選択肢

| 選択肢 | 良い点 | 弱い点 |
|---|---|---|
| **A. パックごとの番号が印刷されていないカードを、M0の対象外にする** | 仮のキーの決まりが単純なまま。最初の題材には影響しない | 旧裏・neo・DP期の買取表は、M0では題材にできない。番号のないプロモが混じれば、そのカードを外すことになる |
| B. DPBP#を番号の代わりに使う | DP期の買取表も題材にできる | DPBP#はポケモンの番号で、同じパックの中でも重なる。カードを一意に決められない |
| C. 番号の代わりの決まりを作る（パック＋カード名＋ワザなど） | どの世代でも題材にできる | 世代ごとに決まりが要り、確かめる手段も少ない。M1でカードDBを作るときに、作り直すことになる |

## 決定

**A にする。** M0の仮のキーで扱うのは、**パックごとの番号が印刷されているカード** だけにする。

- 対象：VS・web・e・ADV・PCG・DPt・LEGEND・BW以降のカードと、番号のあるプロモ。
- 対象外：旧裏・neo、DP（DP1〜DP5、DPのデッキ）、番号のないプロモ。
- 題材の買取表は、対象のカードが中心のものを選ぶ。対象外のカードが混じっていたら、そのカードを正解データから外し、`meta.yaml` に外したカードと理由を記録する。
- LEGENDの、2枚で1体のカード（上と下で別の番号）は、それぞれを1枚のカードとして扱う。

## 理由

- **M0の目的に要らないため。** M0の目的は、クラウドのモデルとローカルのモデルのH0を比べ、カードDBを作るかどうかを判断すること（設計書 6.5）。BW期の買取表で十分に測れる。
- **B を選ばなかったのは、DPBP#ではカードが一意に決まらないため。** DPBP#はポケモンの種類に付く番号で、パックをまたいでも、同じパックの中でも重なる。仮のキーに使うと、違うカードが同じキーになり、採点が誤答を見逃す。誤答を最も重く見るこのタスクでは避けたい。
- **C を選ばなかったのは、M1でカードDBを作るときに、作り直すことになるため。** 番号のないカードの表し方は、カードDBの `card_id` の設計で決めるべきこと。M0で仮の決まりを作っても、使い捨てになる。
- **外したカードを記録するのは、** 成績の母数が変わったことを、あとで追えるようにするため。

## 影響

- 買取表を選ぶとき（TODO 8章）に、カードの世代と、パックごとの番号があるかを確かめる。
- 正解データの作成ルール（`docs/gold-guideline.md`）に、対象外のカードの見分け方、外し方、記録の仕方を書く。
- M1のカードDBの設計で、番号のないカードの表し方を決める。そのときの材料：`card_id` を番号から作らずDBが発行する、印刷されている番号はそのまま持つ、番号の形の種類（パックごと、プロモ、DPBP#、なし）を別に持つ、DPBP#はポケモンの属性として持つ（調査の5章）。
- 見直すきっかけ：M1でカードDBを作るとき。旧裏・neo・DP期の買取表を題材にしたくなったとき。
