# 0006. クラウドのモデルの認証：APIキーかサブスクか

- ステータス：提案
- 日付：2026-10-26
- 決定者：kajiwara

## 背景

- 設計書では、手元のサブスク認証のまま実行する方針だった（設計書 7.2）。
- 被験エージェントは、隔離された環境やクラウドのサーバーで無人実行する（[0003](0003-isolated-execution-environment.md)、[0005](0005-gpu-environment.md)）。
- QCDの「コスト」を測るには、トークン数や費用を正確に取れるほうがよい。

## 検討した選択肢

| 選択肢 | 良い点 | 弱い点 |
|---|---|---|
| サブスク認証 | 追加の費用がかからない（利用枠の範囲内） | サーバーでの無人実行が利用規約上できるか確認が必要。利用枠を普段の作業と取り合う。費用を正確に測りにくい |
| APIキー（従量課金） | 無人実行に向いている。トークン数と費用を正確に記録できる | 実行するたびに費用がかかる。キーを安全に管理する必要がある |

## 決定（提案）

おすすめは **APIキー**。M0の規模なら費用は小さく、QCDのコストも正確に測れる。

採用にするために必要なこと：

- M0の実行回数から、API代を見積もる
- API代を月1万円の予算に含めるかを決める
- APIキーの管理方法を決める（例：AWS Secrets Manager、またはSSMパラメータストア）

## 影響

- 設計書 7.2（サブスク認証で動かす）を見直す。
- 実行記録（`run.yaml`）にトークン数と費用を残す（設計書 5.5）。
- APIキーはリポジトリに入れない。
