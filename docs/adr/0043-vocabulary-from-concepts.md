# 0043. 語彙の値の一覧は、調べた概念の一覧と「その他」で作る（0027の一部を置き換え）

- ステータス：採用
- 日付：2026-10-30
- 決定者：kajiwara
- 関係するADR：[0027](0027-provisional-key-variant.md)（仕様の軸）、[0030](0030-task-spec-in-yaml.md)（値の一覧はスキーマだけが持つ）、[0042](0042-out-of-vocabulary-values.md)（語彙の外の値の扱い）

## 背景

- `output.schema.json` の語彙の値の一覧は、被験エージェントが答えを言い表すための言葉そのものである。答えるときにモデルが読み、採点するときに採点器が確かめる。
- [0027](0027-provisional-key-variant.md) では、加工とスタンプの値は「題材に出てきたものから足す」と決めた。今の加工の一覧は `ノーマル` と `指定なし` だけで、ミラーのカードを見ても、モデルはそれを言い表せない。
- 題材に出てきたものから足す決まりには、次の問題がある。
  - 一覧が足りず、正しい答えを言い表せない。
  - サンプルが増えるたびに一覧が変わり、前の結果と比べにくくなる。
  - 一覧に値が足されたこと自体が、「どこかのサンプルの答えにその値がある」というヒントになる。
- 一方で、モデルの言い回しのゆれ（「ミラー」「ミラー加工」「リバースホロ」）の範囲は、特定できない。一覧を言い回しで作ろうとすると、必ず漏れる。

## 検討した選択肢

| 選択肢 | 良い点 | 弱い点 |
|---|---|---|
| A. 題材に出てきた値から足す（今まで） | 手間が小さい | 上の3つの問題がある |
| B. モデルの言い回しをできるだけ集めて、一覧に入れる | 言い換えを救える | 言い回しの範囲は特定できず、必ず漏れる。同じ概念に名前が複数でき、採点器が同じものだと知る必要がある |
| **C. 調べた概念の一覧を、概念ごとに1つの決まった名前で作る。漏れた概念のために「その他」を用意する** | 概念は有限で、調べられる。モデルは言い回しを当てるのではなく、一覧から選べばよい。サンプルが増えても一覧が変わらない | 概念を調べる手間がかかる |

## 決定

**C にする。** [0027](0027-provisional-key-variant.md) の「加工とスタンプの値は、題材に出てきたものから足す」を置き換える。

- 語彙の値の一覧は、**調べた概念の一覧** から作る。**1つの概念には、1つの決まった名前** を付ける。同じ概念に、別の名前を足さない。
- 加工の一覧は、世代ごとの加工の種類を調べて作る。
- 調べきれない概念のために、「その他」の値を用意する。
  - 加工：`その他の加工`（ノーマルではないとわかるが、種類が一覧にない、または見分けられない）
  - スタンプ：`その他のスタンプ`（スタンプが押されているとわかるが、どのスタンプか一覧にない、または見分けられない）
- 「その他」の値の成績での扱い（[0039](0039-deliverables-and-intermediates.md) に従う）：
  - 「その他」は「ノーマルではない（スタンプがある）」ことだけを断定し、種類は断定していないとみなす。
  - 正解が `ノーマル`（`なし`）なら、断定が間違っているので **誤答**。
  - 正解が具体的な種類なら、種類を断定していないので、その軸は **保留**。
  - 正解が `指定なし` なら、比べない。
- 一覧を直すきっかけは、調べ直したとき、または診断で「一覧にない概念」が見つかったとき（[0042](0042-out-of-vocabulary-values.md)）。直したら、`task.yaml` の `version` を上げる。

## 理由

- **言い回しではなく概念で一覧を作れば、範囲を決められるため。** 言い回しは無限にあるが、加工の種類は有限で、調べられる。モデルは一覧から選べばよく、言い回しのゆれは問題にならない。B を選ばなかったのはこのため。
- **概念ごとに1つの名前にするのは、** 採点器が「同じものか」を判断せずに済むようにするため。
- **「その他」を用意するのは、** 調べた一覧にも漏れはありうるため。「その他」があれば、モデルは、確かめた事実（ノーマルではない）だけを、推測を入れずに言い表せる。
- **サンプルに合わせて一覧を変えないのは、** 前の結果と比べられるようにし、答えのヒントを与えないため。A を選ばなかったのはこのため。

## 影響

- 今の一覧に、`その他の加工` と `その他のスタンプ` を足す。
- 世代ごとの加工の種類の調査（TODO 1.4）を、語彙の一覧を作るための作業として行い、その結果で加工の一覧を作る。
- `gold-guideline.yaml` の G-06（一覧にない値が出てきたとき）を、この決まりに合わせて直す。
- `gold-draft/prompt.md` の値の一覧にも、「その他」の値を足す。
