# 0036. スタンプは画像に見当たらなければ「なし」とし、この基準を被験エージェントにも伝える

- ステータス：採用
- 日付：2026-10-30
- 決定者：kajiwara
- 関係するADR：[0027](0027-provisional-key-variant.md)（仕様の軸と「指定なし」）、[0030](0030-task-spec-in-yaml.md)（タスクの仕様）、[0032](0032-separate-files-by-reader.md)（読み手ごとのファイル）

## 背景

- 仕様は、版・加工・スタンプの3つの軸で持ち、確かめられない軸は「指定なし」にする。「なし」は確かめた結果その仕様がないとき、「指定なし」は確かめられないとき（[0027](0027-provisional-key-variant.md)）。
- 1枚目のサンプル（`magi-nagoya-20261030`）の正解データを確かめるときに、スタンプを「なし」にした。根拠は次の2つ。
  - スタンプは、配布元のロゴなどがカードの絵の上に大きく押される（013/XY-P のデデンネなど）。この解像度でも、押されていれば見えるが、40枚とも見当たらなかった。
  - 照合の結果、40枚とも拡張パックのカードだった。スタンプが押されるのは、主にプロモ。
- 一方で、版（1EDのマーク）と加工は、画像では確かめられなかったので「指定なし」にした。
- しかし、被験エージェントに渡す決まり（`spec.yaml` の R-09）には、「画像で確かめられない軸は指定なし」としか書いていなかった。そのため被験エージェントは、スタンプも「指定なし」と答えると考えられる（実際、下書きのLLMもそう答えた）。
- 正解の軸が「指定なし」でなければ、採点ではその軸も比べる（[0027](0027-provisional-key-variant.md)）。正解データだけスタンプを「なし」にすると、パックと番号を当てても、スタンプの軸が合わない。被験エージェントに伝えていない基準で採点することになる。

## 検討した選択肢

| 選択肢 | 良い点 | 弱い点 |
|---|---|---|
| A. 正解データのスタンプも「指定なし」にする | 被験エージェントの答えと合う。決まりを足さずに済む | 画像で確かめられることを、確かめられないことにしてしまう。Card Pulse で必要な情報（スタンプがない）を捨てることになる |
| B. 正解データだけ「なし」にする | 確かめた事実を正解データに残せる | 被験エージェントに伝えていない基準で採点することになり、正しく答えても合わない |
| **C. 「スタンプは画像に見当たらなければなし」という基準を決め、正解データと被験エージェントの両方に同じ基準を使う** | 確かめた事実を残せる。被験エージェントも同じ基準で答えられ、公平に採点できる | 被験エージェントに渡す決まりと、正解データの決まりの両方を直す必要がある |

## 決定

**C にする。**

- **スタンプは、画像に見当たらなければ「なし」、画像が粗くて見分けられなければ「指定なし」にする。**
- **版と加工は、これまで通り、画像で確かめられなければ「指定なし」にする。**
- **正解データの値を決める基準は、被験エージェントに伝えている基準と同じにする。** 照合先で調べてわかったことでも、被験エージェントに伝えている基準で画像から決められない値は、正解データに入れない。
- この基準を、次のファイルに書く。
  - 被験エージェントに渡す側：`spec.yaml` の R-09（被験ハーネスのプロンプトの元）、`output.schema.json` のスタンプの説明（モデルの呼び出しに渡す）
  - 正解データの側：`gold.schema.yaml` のスタンプの説明（定義）、`gold-draft/prompt.md`（下書きのLLM）、`gold-guideline.yaml` の G-10（人が確かめるとき）

## 理由

- **被験エージェントに伝えていない基準で、採点しないため。** 採点で比べる値は、被験エージェントが同じ決まりに従えば答えられるものでなければならない。B を選ばなかったのはこのため。
- **画像で確かめられることは、確かめたものとして残すため。** スタンプは絵の上に大きく押されるので、ないことも画像で確かめられる。これを「指定なし」にすると、確かめられる情報を捨てることになる。Card Pulse では、スタンプのあるカードとないカードで価格が違う。A を選ばなかったのはこのため。
- **版と加工を「指定なし」のままにするのは、** 1EDのマークは小さく、加工の種類は光り方だけでは見分けにくく、どちらも買取表の画像では確かめられないことが多いため。スタンプとは、画像で見える大きさが違う。

## 影響

- 1枚目のサンプルの正解データは、40枚とも、版「指定なし」、加工「指定なし」、スタンプ「なし」とする。
- 被験エージェントがスタンプを「指定なし」と答えた場合の扱いは、[0027](0027-provisional-key-variant.md) の「決めるために必要なこと」（その軸は不明と同じに扱う案）に従う。採点器を作るときに決める。
- **これからも、正解データの値の決め方を変えたり足したりするときは、被験エージェントに渡す決まり（`spec.yaml`、`output.schema.json`）も、同じ基準になるように直す。**
- 見直すきっかけ：画像が粗く、スタンプの有無を見分けられない買取表が増えたとき。
