# 0003. 実行基盤：隔離された環境で動かし、モデルのサーバーと分ける

- ステータス：採用
- 日付：2026-10-26
- 決定者：kajiwara

## 背景

被験エージェントを作業用のPCでそのまま動かすと、次の問題がある。

- **自分の環境に影響が出る**：エージェントが自分のファイルやフォルダを消したり書き換えたりするおそれがある。
- **設定が混ざる**：普段使っているClaude Codeの設定（グローバルの `CLAUDE.md`、メモリ、プラグイン、MCPの設定など）が被験エージェントに読み込まれる。H0が「素の状態」でなくなり、結果も再現できなくなる。

また、ローカルのモデルを動かすにはGPUが要る（[0002](0002-compare-cloud-and-local-models.md)）。ただし、隔離が必要なのはファイルを書き換える可能性があるエージェントのほうで、モデルのサーバーは推論の結果を返すだけである。

## 検討した選択肢

| 選択肢 | 良い点 | 弱い点 |
|---|---|---|
| 作業用のPCでそのまま動かす | 手間がない | 自分の環境に影響が出る。設定が混ざる |
| 作業用のPCでコンテナやVMの中で動かす | 費用がかからない | MacのDockerはGPUを使えない。IaCの経験が限られる |
| 外部のサーバー（クラウドのVMなど）で動かす | 作業用のPCから完全に切り離せる | 費用がかかる。サーバーの管理が必要 |

## 決定

- 被験エージェントと実行スクリプトは、**作業用のPCから隔離された環境**（コンテナやVM）で動かす。普段のClaude Codeの設定は持ち込まない。
- **エージェントの実行環境** と **モデルのサーバー** は分けて考え、置き場所は別々に決められるようにする。
- どこに置くか（AWSかWindows PCかなど）は [0005](0005-gpu-environment.md) で決める。

## 影響

- 実行ごとに新しい作業ディレクトリを作る方針（設計書 3.2, 7.1）は、隔離された環境の中で行う。
- 被験エージェントに渡す設定（プロンプト、ツール、MCPの設定）は、構成ファイルから毎回組み立てる。
- 隔離された環境の構築は、IaCで自動化する（[0004](0004-infrastructure-as-code.md)）。
