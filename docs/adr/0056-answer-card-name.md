# 0056. 答えのカードに、カードの名前（name）を足す

- ステータス：採用
- 日付：2026-11-03
- 決定者：kajiwara
- 関係するADR：[0026](0026-provisional-key-pack-number-variant.md)（仮のキー：パック＋番号＋仕様）、[0047](0047-output-reading-and-answer.md)（reading と answer）、[0057](0057-answer-card-name-is-graded.md)（答えの名前も成績で比べる）

## 背景

- 答えの「何のカードか」（`answer.card`）は、パック・番号・仕様だけで表していた（[0026](0026-provisional-key-pack-number-variant.md)、[0047](0047-output-reading-and-answer.md)）。名前を入れていなかったのは、次の理由からである。
  - 名前では、カードが決まらない（同じ名前のカードが、別のパックにもある）。
  - パック・番号・仕様が決まれば、名前も決まる。
  - 同じことを2か所に書くと、食い違いが起きうる。
  - 画像から読んだ名前は、別の欄（`reading.name`）にある。
- ただ、この形では、答えが人に読みにくい。たとえば、印刷名を「ツボシボ」と読み違えたが、カードは正しく特定した答えは、次のようになる。

```json
"reading": {"name": "ツボシボ", "price_text": "6,000円"},
"answer": {"card": {"pack": "ハートゴールドコレクション", "number": "011/070", "variant": {…}}, "price_jpy": 6000}
```

- 011/070はツボツボというカードなので、答えは正しい。しかし、答えに名前がないので、人が読むと「ツボシボ」という間違ったカードを答えたように見えてしまう。実際に、議論の中でも、そう読み違えた。

## 検討した選択肢

| 選択肢 | 良い点 | 弱い点 |
|---|---|---|
| A. 今のまま（名前を足さない） | 食い違いが起きない | 答えが人に読みにくい。読み取りの誤りと、答えの誤りを取り違えやすい |
| **B. カードを表す形（`card`）に、名前を足す** | 答えも候補も、名前でひと目で分かる | 名前と、パック・番号が食い違うことがある（[0057](0057-answer-card-name-is-graded.md) で扱う） |
| C. 答え（`answer`）の直下に、名前の欄を足す | 答えは名前で分かる | 候補（`candidates`）には名前が付かない |

## 決定

**B にする。**

- カードを表す形（出力のスキーマの `card_ref`）に、`name` を足し、必ず書く。候補（`candidates`）も同じ形なので、候補にも名前が付く。
- `answer.card.name` には、**特定したカードの正式な名前**（そのカードに印刷されている名前）を書く。画像で読めなかった部分（EXなど）も、知識で補って書く。
- `reading.name` は、これまでどおり、**画像に印刷されている通りに読んだ名前** を書く。知識で補わない。

| 欄 | 中身 | 知識で補うか | 例（ツボシボの場合） |
|---|---|---|---|
| `reading.name` | 画像から読んだ名前（途中式） | 補わない | ツボシボ（読み違い） |
| `answer.card.name` | 特定したカードの、正式な名前（答え） | 補う | ツボツボ |

足したあとの答えは、次のようになる。

```json
"reading": {"name": "ツボシボ", "price_text": "6,000円"},
"answer": {
  "status": "identified",
  "card": {"name": "ツボツボ", "pack": "ハートゴールドコレクション", "number": "011/070", "variant": {…}},
  "price_jpy": 6000
}
```

「読み取りはツボシボ、答えはツボツボ」と、ひと目で分かる。

## 理由

試験に見立てると、名前のない答えは、「この元素は何か」という問いに「原子番号6」とだけ答えるのに近い。

| 試験 | このタスク |
|---|---|
| 途中式に書き写した元素の名前 | 印刷名（`reading.name`） |
| 答えの原子番号。番号だけで、元素は1つに決まる | 答えのパック・番号。パック・番号だけで、カードは1つに決まる |
| 答えに添えた元素の名前 | 答えのカードの名前（`answer.card.name`） |

- 「原子番号6」だけでは、採点する人は、6が何かを調べないと分からない。途中式で「炭素」を「灰素」と書き間違えていれば、答えまで間違えたように見える（背景の、ツボシボの例）。
- 「原子番号6（炭素）」と書けば、ひと目で分かる。
- 「原子番号6（窒素）」と書いてあれば、番号と名前のどちらかが間違っていると分かる。

名前を足して良くなることを、選択肢ごとにまとめると、次のとおり。

| 良くなること | A. 足さない | **B. `card` に足す** | C. `answer` の直下に足す |
|---|---|---|---|
| 答えを、人がひと目で読める | × | ○ | ○ |
| 検算になる | × | ○ | ○ |
| どのカードのつもりで答えたかが分かる | × | ○ | ○ |
| 知識で補った名前を、印刷名とは別の場所に書ける | × | ○ | ○ |
| 候補も、名前で読める | × | ○ | × |

それぞれの理由は、次のとおり。

- **答えを、人がひと目で読めるようにするため。** 答えは、人が診断で読み、ハーネスを直すときの材料にする（[0047](0047-output-reading-and-answer.md)）。パックと番号だけでは、どのカードを答えたのかが、すぐに分からない。A を選ばなかったのはこのため。
- **読み取りの誤りと、答えの誤りを、取り違えないようにするため。** 名前がないと、読み取りで読み違えただけなのに、答えまで間違えたように見える。
- **検算になるため。** 名前とパック・番号は、同じカードを別の言い方で表したものである。2つが食い違えば、どこかが間違っていると分かる。名前がなければ、パック・番号の間違いは、答えの中からは見つけられない。
- **どのカードのつもりで答えたかが、分かるため。** M0にはカードDBがないので、パック・番号が正解と違うとき、それが何のカードかを、機械では調べられない。名前があれば、たとえば次の2つを見分けられる。
  - 名前は正解と合うが、パック・番号が違う：同じ名前の別のカードを選んだ。1枚目でも、L-Pのプロモに同じ名前・HPのカードがある5枚で起こりうる。
  - 名前は正解と違うが、パック・番号は合う：答えの中で食い違っている（[0057](0057-answer-card-name-is-graded.md)）。
- **知識で補った名前を、印刷名とは別の場所に書けるようにするため。** これまでは、モデルが「ギラティナEX」だと知っていても、名前を書ける場所は印刷名しかなかった。そこにEXを書けば、印刷名を知識で補ったことになる。答えに名前を書く場所があれば、知識で補った名前はそこに書き、印刷名は画像の通りに保ちやすくなる。
- **候補にも名前を付けるため。** 候補は、特定できないときに、どのカードで迷ったかを示す。名前があれば、迷い方が読める。C を選ばなかったのはこのため。
- **名前と、パック・番号の食い違いは、成績で扱えるため。** 名前を足すと、名前と番号が別のカードを指す答えを書けてしまう。これは、答えの名前も成績で比べることで扱う（[0057](0057-answer-card-name-is-graded.md)）。

## 影響

- `output.schema.json` の `card_ref` に `name`（必須）を足し、出力の例を直す。
- タスクの仕様（`spec.yaml`）の R-04 を、読み取った名前（`reading.name`）の決まりだとはっきりさせる。特定したカードの名前（`answer.card.name`）の決まりを、R-13 として足す。
- 出力の形が変わるので、`task.yaml` と `spec.yaml` の `version` を上げる。
- H0のプロンプトで、2つの名前の違いを伝える（TODO 9章）。
