# 0039. 成績は成果物（何のカードか・価格）で決め、中間結果（位置・印刷名・HP・ワザ・価格の文字）は診断に使う

- ステータス：採用
- 日付：2026-10-30
- 決定者：kajiwara
- 関係するADR：[0026](0026-provisional-key-pack-number-variant.md)（仮のキー）、[0027](0027-provisional-key-variant.md)（仕様の軸）、[0038](0038-score-by-assertion.md)（正解・保留・誤答）、[0040](0040-intermediate-results-for-diagnosis.md)（段階ごとの中間結果）

## 背景

- 成績は「エージェントが断定した答えを、そのまま確定データとして使ってよいか」で決める（[0038](0038-score-by-assertion.md)）。そのためには、出力のうち何が「確定データになる答え」かを決める必要がある。
- 出力には、確定データになるもの（どのカードか、価格）と、それを作る途中で読んだもの（印刷されたカード名、HP、ワザ）がある。出力のスキーマも、画像から読んだもの（`reading`）と、答え（`answer`）を分けている（設計書 5.2、[0047](0047-output-reading-and-answer.md)）。
- これまで、誤答はカードの特定だけで決めていた。しかし、正しいカードに間違った価格が付くことも、確定データを汚す。
- カードを不明と答えながら、価格だけ断定して間違えるという、境目の場合もありうる。

## 検討した選択肢

| 選択肢 | 良い点 | 弱い点 |
|---|---|---|
| A. 成績は、カードの特定だけで決める（今まで） | 単純 | 価格の読み違いが、確定データを汚すのに、成績に出ない |
| B. 成績は、出力のすべての項目で決める | 厳しい | カード名やHPの読み違いは、それだけでは確定データを汚さない。成績が、確定データとして使えるかを表さなくなる |
| **C. 出力の項目を成果物と中間結果に分け、成績は成果物だけで決める。中間結果は診断に使う** | 成績が、確定データとして使えるかをそのまま表す。中間結果で、どこで外れたかを見つけられる | 項目をどちらに入れるかを、タスクごとに決める必要がある |

## 決定

**C にする。**

| | 項目 | 使い道 |
|---|---|---|
| **成果物**（確定データになるもの） | 何のカードか（パック・番号・仕様の各軸）、価格 | 成績 |
| **中間結果**（成果物を作る途中で読んだもの） | 位置、格子の大きさ、印刷されたカード名・HP・ワザ、印刷されている価格の文字（[0040](0040-intermediate-results-for-diagnosis.md)） | 診断 |

カードごとの成績は、次の順で決める。

1. **誤答**：成果物のうち、断定した値が1つでも正解と違う。
   - `status` が `identified` で、パックか番号が違う
   - 仕様の軸を断定して（「指定なし」以外の値を出して）、正解と違う。ただし、正解が「指定なし」の軸は比べない
   - 価格を断定して（null 以外の値を出して）、正解と違う。**カードを不明と答えていても、価格を断定して間違えたら誤答** とする
2. **保留**：誤答ではなく、成果物のうち、正解には値があるのに断定しなかったものがある。
   - `status` が `unknown`
   - 正解に値がある仕様の軸を「指定なし」とした
   - 正解に価格があるのに、価格を null とした
   - 形式の誤りで、そのカードを受け取れなかった（[0041](0041-format-error-kinds-and-units.md)）
3. **正解**：上のどちらでもない。成果物をすべて断定し、すべて正しい（正解が「指定なし」の軸を除く）。

- 中間結果（カード名、HPなど）の読み違いは、それだけでは誤答にしない。診断で「読み取りの誤り」として記録する。
- 正解が「指定なし」の軸に、出力が値を断定したときは、比べない。ただし、画像で確かめられないはずの値なので、診断で「知識による補完の候補」として記録する。

## 理由

- **成績が、確定データとして使えるかをそのまま表すようにするため。** 確定データになるのは、どのカードかと価格である。B を選ばなかったのは、中間結果の読み違いで、確定データとして使える答えまで誤答になるため。
- **価格の読み違いを誤答に入れるのは、** 正しいカードに間違った価格が付くと、確定データが気づかれないまま汚れるため。A を選ばなかったのはこのため。
- **不明のカードでも、価格を断定して間違えたら誤答にするのは、** 断定した答えが間違っていることに変わりはないため。保留にすると、人がカードを確かめるときに、価格の誤りを見落とすおそれがある。
- **中間結果を診断に使うのは、** 成果物が外れたとき、中間結果を見れば、どの段階で外れたか（読み取りか、照合か）がわかるため（[0040](0040-intermediate-results-for-diagnosis.md)）。

## 影響

- 採点器は、カードごとに上の順で成績を決め、成果物の項目ごとに、合っていたか・断定したかを記録する。
- どの項目が成果物で、どれが中間結果かは、タスクごとに決める。このタスクでは上の表のとおり。2つ目のタスクを作るときに、`spec.yaml` か `task.yaml` に書く形を決める。
