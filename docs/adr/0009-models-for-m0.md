# 0009. M0で使うモデル：Claude Opus 5.5 と Qwen3.8-27B

- ステータス：採用
- 日付：2026-10-26
- 決定者：kajiwara
- 調査：[ローカルのマルチモーダルモデルの候補](../research/local-multimodal-models.md)、[クラウドのモデルのAPI代](../research/cloud-model-api-cost.md)

## 背景

M0では、クラウドのモデル1つとローカルのマルチモーダルモデル1つを比べる（[0002](0002-compare-cloud-and-local-models.md)）。具体的なモデルを決める必要がある。

- ローカルのモデルを動かすGPUは、L4（VRAM 24GB）（[0005](0005-gpu-environment.md)）。
- タスクでは、日本語のカード名、HP、ワザ名、価格を、小さな文字まで読み取る必要がある（設計書 2章）。

## 検討した選択肢

ローカルのモデル（VRAM 24GBの場合）：

| 選択肢 | 良い点 | 弱い点 |
|---|---|---|
| Qwen3.8-27B（4ビット量子化、Ollama、約18GB） | Qwen系は日本語の文字の読み取りの評価で他の系統を大きく上回る。Apache 2.0 | 2026年8月公開。24GBに画像と出力まで収まるかは要確認。vLLM向けの公式の4ビット版は24GBに収まらない |
| Qwen3.5-9B（量子化なし、vLLM、約19GB） | 小さく、動かしやすい。10GBのGPUでも4ビットなら動く | 27Bより性能が低い見込み |
| Gemma 4 12B | 学習データの時期（2025年1月まで）が公開されている | 1枚の画像に使えるトークンが1,120までで、21枚の格子では1枚あたり約50トークンになり、小さな文字を読めない恐れがある。日本語の文字の読み取りの評価が低い |
| InternVL3.5-8B など | 小さい | 日本語の文字の読み取りの評価が低い |

## 決定

- **クラウドのモデル：Claude Opus 5.5**（`claude-opus-5-5`）。APIキーで呼ぶ（[0006](0006-cloud-model-authentication.md)）。
- **ローカルのモデル：Qwen3.8-27B**（4ビット量子化）を、g6.xlarge上の **Ollama** で動かす。
- **予備のモデル：Qwen3.5-9B**。Qwen3.8-27Bが24GBに収まらないときや、Windows PC（[0005](0005-gpu-environment.md) の予備）で動かすときに使う。

## 影響

- **思考の扱いが2つのモデルで違う。** Opus 5.5は、出力の前に考える処理（拡張思考）を切れない。量は `effort` で調整する（既定は `medium`）。Qwen3.5以降は既定で考えてから答えるので、JSONを得るには、思考を切るか、推論サーバーで思考と答えを分ける。どちらの設定にしたかを `run.yaml` に残し、結果を読むときに考慮する。
- **Ollamaのコンテキスト長は必ず明示する**（`num_ctx`）。既定値が小さく、画像と出力が収まらない恐れがある。
- **学習データの時期が公開されていない。** モデルの学習時期より後に出たカードを含める方針（設計書 10.3）のため、発売時期の違うカードについてモデルに聞き、知識がどこまであるかを確かめる。
- **最初の試しの実行で確かめること**：24GBに収まるか、小さな文字を読めるか、JSONを安定して出せるか、1回の所要時間。結果によっては予備のモデルに切り替え、このADRを置き換える。
- モデルのライセンスは、使う前に確認する（TODO 2章）。
