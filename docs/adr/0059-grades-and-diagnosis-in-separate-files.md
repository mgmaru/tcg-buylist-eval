# 0059. 成績と診断は、別のファイル（metrics.json と diagnosis.json）に出す（0023の一部を置き換え）

- ステータス：採用
- 日付：2026-11-04
- 決定者：kajiwara
- 関係するADR：[0023](0023-grader-interface.md)（採点器の入出力）、[0033](0033-grading-by-grader-not-langfuse.md)（採点は採点器が行う）、[0037](0037-results-and-diagnosis.md)（成績と診断の2つを出す）、[0058](0058-grading-flow-by-stage.md)（採点の流れ）
- 採点の段階：全体。段階0〜2の結果を、どのファイルに書くか

## 背景

- 採点器は、成績と診断の2つを出す（[0037](0037-results-and-diagnosis.md)）。成績は「断定した答えを、そのまま確定データとして使ってよいか」に、診断は「被験ハーネスのどの部品を直せばよいか」に答える。
- 採点器の `grade` は、1つのサンプルの1回の実行について、`metrics.json` を出すと決めていた（[0023](0023-grader-interface.md)）。`metrics.json` は、タスクが変わっても共通の外側の形（`task`、`sample_id`、各種の版、`run`、`status`、`counts`、`scores`）と、タスクごとの中身（`details`）に分かれる。`details` は、評価用ハーネスが中身を読まない欄である。
- 診断をどこに書くかは、決めていなかった（設計書 8.6 の未定）。
- 成績と診断は、1件の形が違う。

| | 1件が表すもの | 件数 | 例 |
|---|---|---|---|
| 成績 | 正解データのマス1つ | 1マスに必ず1件 | 1-2：誤答（正解データのカードを間違えた）。名前×、パック○、番号× |
| 診断 | 見つけたこと1つ | 1マスに0件のことも、何件もあることもある | 段階2・特定の照合・1-2・直す部品は照合（H2） |

- レポートは、診断の種類ごとの件数と、該当するカードの一覧を出す（[0037](0037-results-and-diagnosis.md)）。一方で、レポートは、タスクの中身を知らなくても動くようにしたい（[0023](0023-grader-interface.md)）。

## 検討した選択肢

| 選択肢 | 良い点 | 弱い点 |
|---|---|---|
| A. `metrics.json` の `details` に、成績と診断を混ぜて入れる | ファイルが1つで済む | 読むものが違うのに混ざる。診断の種類が増えるたびに、成績のファイルの形も変わる。レポートは `details` を読まないので、診断を出せない |
| B. `metrics.json` の中で、成績の欄と診断の欄を分ける | ファイルは1つで、中は分かれる | 診断の形を変えると、成績のファイルの版も上がる |
| **C. ファイルを分ける。成績は `metrics.json`、診断は `diagnosis.json`** | 答える問いも、読むものも、変わる速さも違うものを、別々に扱える | ファイルが2つになる。同じ実行の2つを、つなぐ必要がある |

## 決定

**C にする。**

- `grade` は、1つのサンプルの1回の実行について、次の2つのファイルを出す。

| ファイル | 中身 | 1件が表すもの |
|---|---|---|
| `metrics.json` | 成績：カードごとの成績、足し算できる件数（`counts`）、その答案の率（`scores`） | 正解データのマス1つ |
| `diagnosis.json` | 診断：段階0〜2で見つけたことの一覧 | 見つけたこと1つ |

- 2つのファイルの外側の形のうち、どの実行のどのサンプルかを表す部分（`task`、`sample_id`、各種の版、`run`）は、同じにする。2つは、`run` の `run_id` と `sample_id` でつなぐ。
- 診断は、`metrics.json` には入れない（`details` にも入れない）。
- `summarize` は、これまでどおり `metrics.json` を足して、`summary.json` を作る（[0023](0023-grader-interface.md)）。
- 診断を、被験構成ごとにどうまとめるか（`summarize` が数えるか、レポートが `diagnosis.json` を読むか）と、1件の記録の形は、診断のスキーマと一緒に決める（TODO 11章）。
- Langfuse に送るのは、これまでどおり `metrics.json` の `scores` である（[0033](0033-grading-by-grader-not-langfuse.md)）。

## 理由

試験に見立てると、`metrics.json` は答案1枚の採点結果（どの問題が○か×か）で、`diagnosis.json` は同じ答案に書き込む赤ペンのメモ（どこで、なぜ間違えたか）にあたる。採点結果は成績表に写して、ほかの生徒と比べる。メモは、次にどう直すかを考えるのに使う。

| | A. 混ぜる | B. 欄を分ける | **C. ファイルを分ける** |
|---|---|---|---|
| 成績と診断が、見て分かれるか | 分かれない | 分かれる | 分かれる |
| 診断を足したとき、成績のファイルの形が変わるか | 変わる | 変わる（版が上がる） | 変わらない |
| レポートが、タスクを知らずに診断を読めるか | 読めない（`details` にある） | 読める | 読める |
| ファイルの数 | 1 | 1 | 2 |

- **答える問いと、読むものが違うため。** 成績は、合格の判定と、構成どうしの比較に使う。`summarize`、Langfuse、比較表が読む。診断は、被験ハーネスを直す人が読む（[0037](0037-results-and-diagnosis.md)）。A を選ばなかったのはこのため。
- **成績の形を、なるべく変えないため。** 成績の形は、構成どうしを比べる物差しである。一方、診断の種類は、これからも増える。これまでも、[0040](0040-intermediate-results-for-diagnosis.md)、[0045](0045-card-name-strict-match.md)、[0046](0046-gold-in-candidates-diagnosis.md)、[0055](0055-competing-answers-for-one-cell.md)、[0057](0057-answer-card-name-is-graded.md) と増えてきた。ファイルを分ければ、診断を足しても、成績のファイルは変わらない。B を選ばなかったのはこのため。
- **1件の形が違うため。** 成績は1マスに1件、診断は見つけたことごとに0件以上である。別のファイルにすれば、それぞれに合った形にできる。
- **ファイルが2つになる弱い点は、つなぎ方で補うため。** 2つのファイルに、どの実行のどのサンプルかを表す同じ部分を持たせ、`run_id` と `sample_id` でつなげば、同じ実行の結果だと分かる。

## 影響

- [0023](0023-grader-interface.md) の「`grade` は `metrics.json` を出す」は、この決定で「`grade` は `metrics.json` と `diagnosis.json` を出す」に置き換わる。
- 設計書 8章（8.1 の図、8.5、8.6）と 3.2 を、この形にする。8.6 に、ファイルごとの責務と、誰が作り・誰が読むかの表を足す。
- 結果のフォルダ（`results/<run_id>/`）に、`diagnosis.json` を足す（TODO 11章、設計書 4章）。
- 成績のスキーマ（`metrics.json`）と、診断のスキーマ（`diagnosis.json`）を、それぞれ決める（TODO 11章）。
