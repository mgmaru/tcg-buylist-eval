# 0010. Langfuseの運用：AWS上に自分で立てる

- ステータス：採用
- 日付：2026-10-26
- 決定者：kajiwara
- 調査：[Langfuseの動かし方と画像の扱い](../research/langfuse-hosting.md)

## 背景

記録・採点・比較・観測にLangfuseを使うことは決めている（[0007](0007-use-langfuse-for-scoring-and-tracing.md)）。いつから使うか、どこで動かすか、トレースの送り方、画像を送ってよいかが未定だった。

- 使える機能は、クラウド版の無料プラン（Hobby）でも、自分で立てる無料のオープンソース版でも、ほぼ同じ。私たちが使いたい機能（データセット、実験と比較画面、自作の採点器からのスコア、トレース）は、どちらでも使える。有料のライセンスが必要なのは、監査ログやデータの自動削除などの組織の管理向けの機能だけ。
- 違うのは上限と運用。クラウド版のHobbyは、画面でデータを見られる期間が30日まで、ユーザーは2人まで、使用量は月5万ユニットまで。自分で立てる場合は上限がないが、アップデートとバックアップを自分で行う。
- インフラの構築の経験を積みたい（[0004](0004-infrastructure-as-code.md)）。

## 検討した選択肢

| 選択肢 | 良い点 | 弱い点 |
|---|---|---|
| クラウド版のHobby（日本リージョン） | 費用ゼロ。管理の手間がない。いつでも画面を見られる | 画面で見られるのは30日まで。店舗の画像を外部のサービスに置くことになるので、画像はハッシュ値に置き換えて送る必要がある |
| 自分で立てる：EC2 1台＋docker compose（使うときだけ動かす） | IaCの経験になる。画像を自分のAWSの中に置ける。30日の制限がない | 月約1,000〜2,000円。動かしているあいだしか画面を見られない。アップデートとバックアップを自分で行う |
| 自分で立てる：公式のTerraformモジュール | 公式の構成 | 本番向けの大きな構成（EKSなど）で、月数万円になる見込み。使うときだけ作る運用に向かない |
| 自分で立てる：常に動かす | いつでも画面を見られる | 月約2.5万円で予算を超える |

## 決定

- Langfuseは **AWS上に自分で立てる**（無料のオープンソース版）。
- 構成は **EC2 1台＋docker compose**。Terraformで構築する（公式のTerraformモジュールは使わず、自作する）。
- **使うときだけ動かす。** 評価の実行と結果の分析のときに起動し、終わったら止める。
- **データ用のディスクは残す。** Terraformで削除防止を付け、EBSのスナップショットでバックアップを取る。
- リージョンは、ほかのサーバーと同じ **米国東部（us-east-1）**（[0005](0005-gpu-environment.md)）。
- 画像などの添付は **自分のS3** に置く。
- トレースは、両方のモデルの呼び出しを、LangfuseのPython SDK（v5以降）を使った自作の小さなラッパーから同じ形で送る。
- **構築するのは、採点器とCSVの出力ができてから。** 正式な記録はCSVとし、Langfuseは比較と分析に使う。
- うまくいかなければ、**クラウド版のHobbyに切り替える**。SDKは同じで、送り先とキーを変えるだけで済む。その場合は画像をハッシュ値に置き換えて送る。

## 影響

- 月の費用が約1,000〜2,000円増える。M0全体では月約2,600〜6,300円の見込みで、予算（月1万円）に収まる。
- 結果を見る時間にも費用がかかる。実行の時間だけでなく分析の時間も含めて、起動時間を見積もる。
- 推奨のサーバーは4コア・16GB（t3.xlarge）。8GB（t3.large）で動くかを試し、動けば費用を半分ほどにできる。
- 実行スクリプトがトレースを送る前に、Langfuseを起動しておく必要がある。起動と停止も手順に含める。
- `docker compose down -v` はデータのボリュームごと消すので使わない。ログのローテーションを設定する。
- M2で予算が厳しくなったら、Langfuseの費用も含めて見直す。
