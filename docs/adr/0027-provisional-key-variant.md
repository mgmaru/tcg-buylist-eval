# 0027. 仮のキーの仕様は決まった値で持ち、正解が「指定なし」なら比べない

- ステータス：提案
- 日付：2026-10-29
- 決定者：kajiwara（未決定。PRでレビューする）
- 関係するADR：[0026](0026-provisional-key-pack-number-variant.md)（仮のキーは「パック＋番号＋仕様」）
- 調査：[docs/research/card-data-sources.md](../research/card-data-sources.md)

## 背景

- 仮のキーには、1ED・アンリミ・ミラーなどの **仕様** を含める（[0026](0026-provisional-key-pack-number-variant.md)）。同じパック・同じ番号でも、仕様が違えば価格が違うため。
- ただし、仕様の区別のしかたは、サイトや店によって違う（調査の2章）。
  - 遊々亭は、BW期の1EDとアンリミを区別しない。
  - カードラッシュは、商品名に「(1ED)」「(アンリミ)」を書いて区別する。書いていなければ「1EDではないもの、または選べないもの」。
- 買取表も、店によって仕様を書いたり書かなかったりすると考えられる。書かれていなければ、正解データでも仕様を決められない。
- 画像から仕様を読み取れるとも限らない。1EDのマークは小さく、買取表の画像では見えないことが多い。

## 検討した選択肢

| 選択肢 | 良い点 | 弱い点 |
|---|---|---|
| A. 仕様を自由な文字で書く | 何でも書ける | 「1ED」「1st」「初版」のように表記がゆれ、機械で比べられない |
| B. 仕様を必ず決める（「指定なし」を許さない） | キーが常に1つに決まる | 買取表に書かれていなければ、正解データの作り手が推測で決めることになる。物差しに推測が入る |
| **C. 決まった値で持ち、「指定なし」も許す。正解が「指定なし」なら仕様を比べない** | 表記がゆれない。買取表にない情報を推測で埋めずに済む | 「指定なし」のカードでは、仕様の取り違えを測れない |

## 決定

**C にする。**

- 仕様は、次の決まった値から選ぶ。

| 値 | 意味 |
|---|---|
| `指定なし` | 買取表に仕様が書かれておらず、画像からも決められない |
| `標準` | 1EDやミラーなどがない世代・カードで、仕様の違いがない |
| `1ED` | 1EDのマークがあるもの |
| `アンリミ` | 1EDのある世代で、1EDのマークがないもの |
| `ミラー` | ミラー加工のもの（マスターボールミラーなど、種類を分ける必要が出たら値を足す） |

- 値は、`gold.schema.yaml` と `output.schema.json` に、選べる値の一覧として書く。足すときは、両方を同時に直す。
- 採点では、**正解の仕様が `指定なし` のときは、仕様を比べず、パックと番号だけで判定する。** 正解の仕様が `指定なし` 以外のときは、パック・番号・仕様のすべてが合って正解とする。

## 理由

- **A を選ばなかったのは、機械で比べられないため。** 採点器は仮のキーを文字列として比べる。表記がゆれると、合っているのに誤答になる。
- **B を選ばなかったのは、物差しに推測を入れないため。** 正解データは成績を測る物差しで、人が確かめた事実だけを書く（設計書 10.2）。買取表に書かれていない仕様を推測で決めると、モデルが正しく「わからない」と答えても誤答になる。
- **C で「指定なし」なら比べないのは、** 買取表に書かれていない情報で、モデルの成績を測れないため。その一方で、書かれているときは比べる。仕様の取り違えは、間違った価格の紐付けにつながるため。
- **`指定なし` と `標準` を分けたのは、** 「区別がない」ことと「区別があるが、わからない」ことを混ぜないため。M1でカードDBに移すとき、`標準` はそのまま1つのカードに対応するが、`指定なし` は複数のカードの候補が残る。

## 決めるために必要なこと

- **正解の仕様が決まっていて、出力が `指定なし` のときの扱い。** 案：仕様を読み取れなかったとして「不明」と同じに扱う（誤答にはしない）。誤答率を最も重く見る方針に合う。
- **正解が `指定なし` で、出力が `1ED` などを答えたときの扱い。** 案：比べない（正解として扱う）。ただし、知識で補った可能性があるので、失敗の分類（設計書 9.2）の「知識による補完」の候補として記録する。
- **ミラーの種類を、M0で分ける必要があるか。** 最初の題材はBW期で、ミラーはほとんど出ないと考えられる。
- **プロモのスタンプ違いを、値に足すか。** 013/XY-P のデデンネのように、同じ番号でスタンプだけが違うプロモがある（調査の3.3）。案：M0では値を作らず、題材に出てきたら `スタンプ:<配布元>` のような値を足す。

## 影響

- `gold.schema.yaml` と `output.schema.json` に、仕様の欄と、選べる値の一覧を足す。
- 採点器の同定の判定（設計書 8.2）に、仕様の比べ方を足す。
- タスク仕様（`docs/task-spec.md`）に、仕様が書かれていなければ `指定なし` と答えることを書く。
- 正解データの作成ルール（`docs/gold-guideline.md`）に、買取表に書かれた仕様だけを書き、推測では埋めないことを書く。
- 見直すきっかけ：買取表を増やして、ミラーなど新しい仕様が出てきたとき。M1でカードDBに移すとき。
