# 0013. AWSのアカウントは従来の方法で作る

- ステータス：採用
- 日付：2026-10-27
- 決定者：kajiwara

## 背景

- AWSのアカウントを作るとき、サインアップの画面で「Googleで続行」を選んだところ、**新しいAWSエクスペリエンス** という種類のアカウント（プロジェクト「Future Startup」）が作られた。
- 新しいAWSエクスペリエンスには、次の特徴がある（[サインアップ方法の比較](https://docs.aws.amazon.com/accounts/latest/reference/sign-up-for-aws.html)、[プロジェクトのリージョン](https://docs.aws.amazon.com/accounts/latest/reference/project-regions.md)）。

| 項目 | 新しいAWSエクスペリエンス | 従来の方法 |
|---|---|---|
| サインイン | Google・GitHub・AppleなどのID（AWS Builder IDが持ち主になる） | メールアドレスとパスワード |
| ルートユーザー | ない | ある |
| リージョン | 住所の国で決まり、変えられない。日本はシドニー（ap-southeast-2） | 自由に選べる |
| 使えるサービス | 一部に限られる | すべて |
| 組織・IAM Identity Center | AWSが自動で用意して管理する | 自分で有効にして管理する |
| 費用の上限 | 支出の上限を設定できる（超えるとプロジェクトが止まる） | 予算のアラート（通知のみ） |

- GPUサーバーは米国東部（us-east-1）で使うと決めている（[0005](0005-gpu-environment.md)）。新しいAWSエクスペリエンスのままだと、シドニーに固定される。

## 検討した選択肢

| 選択肢 | 良い点 | 弱い点 |
|---|---|---|
| A. 新しいAWSエクスペリエンスのまま、シドニーで使う | 作り直さなくてよい。支出の上限を使える | [0005](0005-gpu-environment.md) のリージョンを見直す必要がある。シドニーのGPUは米国東部より高い可能性が高い。使えるサービスが限られる |
| B. 新しいAWSエクスペリエンスで「高度な機能」を有効にする | すべてのリージョンとサービスが使えるようになる | 元に戻せない。先に有料プランへの切り替えが必要。支出の上限の機能がなくなる。ルートユーザーのないアカウントのまま、独特の制約が残る |
| C. 従来の方法で、別のアカウントを作り直す | リージョンを自由に選べる。標準的な構成で、情報も多い。IaCの経験として、ほかの場面でも使い回しやすい | 作り直す手間がかかる。前のプロジェクトを閉じる必要がある |

## 決定

- AWSのアカウントは、**従来の方法（メールアドレスとパスワード）** で作る。新しいAWSエクスペリエンスは使わない。
- 料金プランは **有料プラン**。無料プランは、使えるサービスが限られ、6か月でアカウントが閉じられ、組織に参加すると自動で有料プランになるため、このプロジェクトに合わない。
- 誤って作った新しいAWSエクスペリエンスのプロジェクト（「Future Startup」）は閉じる。AWS Builder IDは、ほかのAWSのツールでも使うことがあるので残してよい。

## 影響

- **サインアップのクレジット（100ドル）は受け取れなかった。** 新しいアカウントは無料プランの対象外と表示され、クレジットも0ドルだった。AWSのサポートからは、「このアカウントは最初から有料プランとして作られたため、無料プランの特典の対象外。誤って作ったプロファイルが関係している可能性がある」と回答があった。ドキュメントでは有料プランでもクレジットを受け取れるとされているが、これ以上は求めない。
- クレジットがないので、**予算のアラートを最初に作る。** 費用の見込み（M0は月約2,600〜6,300円）は変わらず、予算（月1万円）に収まる。
- 最初の安全対策（ルートユーザーの多要素認証、予算のアラート、請求の情報へのアクセス、作業用のユーザー）は、従来のアカウントの手順で行う。
- サインアップの画面では、「Googleで続行」などのボタンを使わない。今後アカウントを作るときも同じ。
