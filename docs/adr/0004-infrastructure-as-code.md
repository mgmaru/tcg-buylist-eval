# 0004. インフラをIaC化する（ツールの候補：Terraform）

- ステータス：提案
- 日付：2026-10-26
- 決定者：kajiwara

## 背景

- このハーネスのほかにも、今後ハーネスを組む機会が増える見込みがある。ハーネス用のインフラの構築を自動化し、環境構築の時間を短くしたい。その経験も積みたい。
- 隔離された環境（[0003](0003-isolated-execution-environment.md)）やGPUサーバー（[0005](0005-gpu-environment.md)）は、使うときだけ作って終わったら消す運用にすると費用を抑えられる。作り直しが簡単であることが前提になる。

## 検討した選択肢

| 選択肢 | 良い点 | 弱い点 |
|---|---|---|
| Terraform | 利用者が多く、情報が多い。AWS以外にも使えるので、ほかのハーネスでも経験を活かしやすい | 独自の言語（HCL）を覚える必要がある。状態ファイルの管理が必要 |
| AWS CDK | Pythonなどの普通の言語で書ける | AWS専用 |
| CloudFormation | AWSの標準で、追加のツールが要らない | AWS専用。記述が長くなりやすい |
| 手作業で構築する | 最初は速い | 再現できない。IaCの経験にならない |

## 決定（提案）

- インフラはIaCで構築し、手作業での構築はしない。
- ツールは **Terraform** を第一候補とする。サーバーの中の設定はコンテナ（Dockerfile）で定義する。
- 予算のアラート（AWS Budgetsなど）もIaCで作る。

採用にするために必要なこと：

- [0005](0005-gpu-environment.md)（GPU環境）が決まること
- Terraformの状態ファイルの置き場所を決めること

## 影響

- リポジトリに `infra/` を追加する（設計書 4章のディレクトリ構成を見直す）。
- 作成・削除の手順をコマンド1つで行えるようにし、READMEに書く。
- 一番の費用リスクはサーバーの消し忘れなので、予算のアラートと削除の手順を最初に用意する。
