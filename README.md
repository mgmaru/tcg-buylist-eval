# tcg-buylist-eval

**「モデルの性能に頼らず、ハーネスの設計で、品質を保ったまま速く安くタスクをこなせるか」を数字で確かめる。あわせて、そのための評価用ハーネスを、タスクと被験エージェントを差し替えて使い回せる仕組みとして作り上げる。**

最初の題材は、X上に投稿されるポケカの **買取表（buylist）画像** から、掲載されているカードを一意に特定するタスク。

> [!NOTE]
> 現在は設計段階（たたき台）です。実装はまだありません。詳細は [設計書](docs/tcg-buylist-eval-design.md) を参照してください。

## 目的

| 目的 | 内容 |
|---|---|
| **第一の目的：ハーネスの設計が出力に与える影響を確かめる** | 被験ハーネスの作り込み・設計で、出力の品質・速さ・コストがどう変わるかを数字で確かめる。「小さいモデル＋作り込んだハーネス」が「大きいモデル＋素の状態」にどこまで迫れるかを測り、カードDB検索や自己検証などの部品の採否を決める。合格した構成は TCG 価格データ基盤 **Card Pulse** のデータ取り込みに組み込む |
| **第二の目的：エージェント評価用のハーネスの仕組みを作り上げる** | タスクと被験エージェントを差し替えて、同じ方法で何度でも評価できる仕組みを作る。新しい被験エージェントは設定だけで、新しいタスクはタスクセット・出力のスキーマ・採点器を足すだけで追加できるようにする |

M0では第一の目的を優先し、第二の目的は差し込み口の境界を守る形で進めます（設計書 0.3）。

評価は **QCD（品質・速さ・コスト）** で行います。品質は合格ラインで判定し、それを満たす構成の中で時間とコストが最小のものを選びます。間違ったカードに価格が紐付くとデータが気付かれないまま汚れるため、**誤答を最も重く見ます**。

## 用語

- **エージェント** ＝ LLMモデル ＋ ハーネス
- **評価用ハーネス**（評価する側）：試験を運営し、採点し、成績を出す仕組み。このリポジトリの本体
- **被験ハーネス**（評価される側）：モデルと組み合わせてタスクを解く仕組み（プロンプト、カードDB検索ツール、自己検証の手順など）

## タスク

| | 内容 |
|---|---|
| 入力 | 買取表画像1枚（＋任意のメタ情報：店舗名、更新日） |
| 出力 | 掲載カードの一覧（JSON） |

- カード名だけではカードを一意に特定できない（同名カードが複数パックに存在する）ため、主キーはカードDBが発行する `card_id` とする。カードDBがない M0 では「パック名＋カード番号」などの仮のキーを使う。
- 確信が持てない場合は **「不明」と答えてよい**。採点では各カードを **正解・不明・誤答** に分け、**誤答率** を最重要指標とする。

## 被験ハーネスの段階

隣り合う段階の差分が1つだけになるよう、積み上げ式で比較します。

| 段階 | 内容 | ツール |
|---|---|---|
| H0：素の状態 | 画像を渡し、一度に一覧を出させる | なし |
| H1：分割 | 格子を把握させ、1枚ずつ読み取らせる | なし |
| H2：照合 | 読み取った名前・HP・ワザ名でカードDBを検索し、`card_id` を確定させる | カードDB検索 |
| H3：自己検証 | DBの情報と画像の印刷内容を突き合わせ、合わなければ読み直す／「不明」にする | カードDB検索 |

## 主な指標

| 指標 | 定義 |
|---|---|
| 同定正答率 | 正解 ÷ 全枚数 |
| **誤答率** | 誤答 ÷ 全枚数（最重要） |
| 不明率 | 不明 ÷ 全枚数（人間の確認が必要な量） |
| 適合率 | 正解 ÷（正解＋誤答） |
| 所要時間・トークン数 | 実行スクリプトでの計測、Langfuse のトレース |

仮の合格ライン：誤答率 2％以下、同定正答率 80％以上、形式エラー 0件（M0 の結果を見て見直す）。

## ディレクトリ構成（予定）

```
tcg-buylist-eval/
├── docs/        設計書、タスク仕様、正解データの作成ルール
├── schemas/     出力JSONのスキーマ、正解データの列定義
├── tasks/       タスクセット（1買取表＝1フォルダ：meta.yaml / gold.csv / 画像）
├── carddb/      カードDBのスナップショット
├── configs/     被験構成（モデル × 被験ハーネス）
├── subject/     被験ハーネスの部品（プロンプト、カードDB検索MCPサーバー）
├── runner/      実行スクリプト
├── graders/     採点器
├── reporters/   レポート出力（CSV・Markdown）、Langfuse 送信
└── results/     実行結果（git管理外）
```

`subject/` は評価される側、`runner/`・`graders/`・`reporters/` は評価する側です。評価する側が被験ハーネスの中身に依存しないよう分けています。

## マイルストーン

| 段階 | 内容 |
|---|---|
| **M0** | 買取表1〜3枚の正解データを仮のキーで作成し、H0 を2モデルで比較。結果からカードDBを作るか判断する |
| M1 | カードDBと検索ツールを作成、`card_id` へ移行、H2 を追加、Langfuse 連携 |
| M2 | H1・H3 を追加、繰り返し実行でばらつきを測定、タスクを10枚以上に増やし dev/test に分割 |
| M3 | 合格した構成を Card Pulse のデータ取り込みに組み込む |

## 注意事項

- 買取表画像は各店舗の著作物です。公開リポジトリには画像をコミットせず、出典URLと日付だけを残します。
- X やカード公式サイトの利用規約を確認してから、画像の収集やカードDBの作成を行います。
- 再現性のため、Web検索ではなくローカルのカードDBスナップショットを使い、実行条件はすべて記録します。
